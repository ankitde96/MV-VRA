## 1. Scope

Full visual redesign of every page and client component under `app/` and `components/`
(excluding `components/ui/*` internals, which get extended not gutted). Internal console
gets a bold modern-SaaS treatment; vendor portal gets a low-density, high-clarity treatment
per `DESIGN-SYSTEM.md` §1. Does **not** touch `lib/**` (except an optional dashboard
aggregate service if none exists), `app/api/**`, `proxy.ts`, `scripts/**`, or either root
source spec.

## 2. Why

Backend is feature-complete through Phase 11 (190 tests, `HANDOVER.md` 2026-08-17) but the
UI never got a design pass — hand-written `rounded-lg border p-4` panels everywhere, no
`card.tsx`, 9 dead shadcn primitives, dashboard still a 20-line Phase 2 placeholder, roll-up
has zero charts, no loading/error boundaries, sonner mounted and never called, portal leaks
internal vocabulary to vendors. Full findings in `docs/UI-REVAMP-PLAN.md`.

## 3. Plan

See `docs/UI-REVAMP-PLAN.md` in full — 8 phases (0: guardrails/docs, 1: design foundation,
2: app shell, 3: dashboard/rollup, 4: data tables, 5: domain components, 6: forms/feedback,
7: vendor portal, 8: motion/a11y/responsive). Each phase ends `npm run verify` green before
the next starts.

## 4. Flow impact

None — no execution path changes, purely presentational. `FLOW.md` not updated.

## 5. Data model impact

None.

## 7. What didn't work

- 21st.dev MCP catalog search returned `catalog search failed` throughout the build —
  never recovered across the session, so the whole revamp was built on the shadcn registry
  alone. No 21st.dev retrievals were spent.
- `@tanstack/react-table@9.1.2` and `recharts@3.8.0` (whatever `npm i` resolved to at
  session start) were both too new to trust: v9's table API is a ground-up rewrite with no
  `useReactTable`, and v3 recharts changed its DOM/type surface enough to break the shadcn
  `chart.tsx` wrapper outright. Both downgraded to their last stable major
  (`@tanstack/react-table@8.21.3`, `recharts@2.15.4`) — see `DECISIONS.md` 026 below.
- The `resize_window` browser-automation tool did not change the actual rendered viewport
  in this environment — requested 375×812/390×844, screenshots kept returning ~1300px+
  wide. Responsive behavior at narrow widths was verified by code review (the app's
  Tailwind responsive classes and shadcn `Sidebar`'s built-in mobile `Sheet` fallback), not
  by an actual visual check — flagged explicitly rather than claimed as tested.

## 9. Verification

`npm run format:check && npm run lint && npm run typecheck && npm run test && npm run build`

the pre-revamp baseline). One recurring `ENOTEMPTY` on `.storage-local` surfaced during
full-suite parallel runs in three separate phases (offboarding, sharing test files) —
confirmed each time to be a pre-existing test-cleanup race by re-running the affected
suite alone (always passes in isolation), not a regression introduced by this work.
