## 1. The two surfaces

The single most consequential UI decision in this project: **MV-VRA has two audiences with
opposite needs, and they must not share a density.**

|               | Internal console                                | Vendor portal                                  |
| ------------- | ----------------------------------------------- | ---------------------------------------------- |
| User          | Risk analyst, daily, expert                     | Vendor SPOC, a few sessions ever, non-expert   |
| Goal          | Scan and compare many records fast              | Complete one long form without giving up       |
| Density       | High — dense tables, tight rows, full-width     | Low — one section per screen, generous spacing |
| Navigation    | Persistent sidebar, keyboard-driven             | Linear progress, one primary action per screen |
| Line length   | Unconstrained in table cells                    | Capped at 70ch — questions are long prose      |
| Touch targets | 32px acceptable (mouse/keyboard)                | **44px minimum** — likely on a phone or tablet |
| Language      | Jargon fine (`residual score`, `Tier 1`, `CAP`) | Plain language, jargon explained inline        |
| Error tone    | Terse and precise                               | Explanatory, tells them what to do next        |

Same tokens, same components, different density scale and information architecture. A
vendor abandoning a half-finished questionnaire is a business failure, not a UX nit — the
portal gets designed for someone who did not ask to be there.

## 2. Style direction

> **AMENDED 2026-08-18 — see `DECISIONS.md` 037 (supersedes 028).** The confirmed Console
> redesign restores the original Swiss discipline across the product: flat opaque surfaces,
> 1px borders, 8px card radii, no aurora/grain/glass treatment. Risk-semantic colors remain
> unchanged. The action palette is MoneyView green (`#00A15C`) and typography is Geist.
>
> **AMENDED 2026-08-17 — see `DECISIONS.md` 025.** (Partially superseded by 028 above, kept
> for history.) The project owner asked for a bolder, "catchy" enterprise-SaaS treatment
> over the pure-Swiss direction below. Gradient accent bands, `shadow-md` card elevation, a
> larger display type scale, and count-up/entry animation were sanctioned for page headers,
> the dashboard hero, and KPI/stat cards only.

**Minimalism & Swiss Style** (`styles.csv` row 1) remains the base discipline for **tables,
forms, and risk-semantic surfaces**: flat, 1px borders, strict 4px spacing, strong type
hierarchy. Selected originally because the skill's data lists it as best-for "enterprise
apps, dashboards, professional tools", rates it `✓ WCAG AAA`, `⚡ Excellent` performance.

Now layered with **Glassmorphism** (`styles.csv` row — "Modern SaaS, financial dashboards,
high-end corporate... Best For") everywhere else — chrome, hero, cards, overlays. Its own
data flags "⚠ Ensure 4.5:1" as the condition, not a rejection; §3's glass tokens use
high-opacity surfaces specifically so composited text still clears that floor (verified
in-browser per phase, not assumed from the token).

Still excluded, no change:

- **Neumorphism / Claymorphism** — flagged "Do Not Use For: data-heavy dashboards",
  "finance", "legal apps". Soft toy-like depth reads as unserious for a compliance tool.
- **Decorative motion outside the sanctioned set** — count-up, entry stagger, and hover
  feedback are allowed (§3 Motion); ambient/looping decorative animation is not.

## 3. Tokens

### Colour

Base palette from `colors.csv` row 6 (B2B Service — "professional blue + neutral grey"),
chosen over the SaaS-general `#2563EB` blue because a GRC console should read as
institutional rather than consumer.

```js
// tailwind.config.ts — semantic names, not colour names. `bg-primary`, never `bg-slate-900`.
colors: {
  primary:    '#0F172A',   // headers, sidebar, primary text weight
  secondary:  '#334155',   // secondary surfaces, muted headings
  cta:        '#0369A1',   // primary action
  background: '#F8FAFC',   // app background
  surface:    '#FFFFFF',   // cards, table rows
  foreground: '#020617',   // body text
  muted:      '#475569',   // secondary text — the lightest permitted for text
  border:     '#E2E8F0',
}
```

### Risk semantics

The domain palette. These carry meaning, so they are locked and never reused decoratively.

| Meaning           | Text/icon | Surface   | Contrast on white |
| ----------------- | --------- | --------- | ----------------- |
| Tier 1 / Critical | `#B91C1C` | `#FEF2F2` | ~6.6:1            |
| Tier 2 / High     | `#B45309` | `#FFFBEB` | ~5.1:1            |
| Medium            | `#0369A1` | `#F0F9FF` | ~4.6:1            |
| Tier 3 / Low      | `#15803D` | `#F0FDF4` | ~5.0:1            |
| Neutral / N/A     | `#475569` | `#F8FAFC` | ~7.5:1            |

Ratios computed by hand from the sRGB values — **verify in-browser before Phase 3 ships**,
and note `#0369A1` at ~4.6:1 clears AA but not AAA. Use `#075985` if any small text needs to
sit on it.

**Colour is never the only indicator** (`ux-guidelines.csv` #36, and a hard requirement in a
tool used by colourblind reviewers to make risk calls). Every severity is rendered as
`icon + text label + colour` — a red dot alone is not a Tier 1 badge.

### Typography

`typography.csv` row 5 — **Minimal Swiss: Inter, single family, weight variations only**.
Best-for reads "Dashboards, admin panels, enterprise apps, design systems". One family means
one font load, no pairing mismatch, and tabular figures for score columns.

```
Display  30px / 600 / -0.02em
H1       24px / 600
H2       20px / 600
H3       16px / 600
Body     15px / 400 / line-height 1.6
Body-sm  13px / 400 / line-height 1.5    (table cells, metadata)
Mono     13px  ui-monospace              (control_id, IDs, scores)
```

- `font-display: swap` with a matched fallback stack, to avoid FOIT and layout shift
  (`ux-guidelines.csv` #50, #75).
- **Portal body text is 16px minimum**, not 15px — mobile browsers zoom below that.
- `font-variant-numeric: tabular-nums` on every score, count, and date column so digits align.
- Body copy capped at 70ch in the portal (`ux-guidelines` line-length; questions run long).

Alternative if accessibility review asks for more: `typography.csv` row 16, Corporate Trust
(Lexend + Source Sans 3) — Lexend is designed for reading ease. A drop-in swap.

### Spacing, radius, elevation, z-index

- Spacing: 4px scale — `4 8 12 16 24 32 48 64`. Nothing off-scale.
- Radius: `6px` default, `8px` cards, `9999px` badges only. No large radii — Swiss style.
- Elevation: borders first. Shadows only on genuinely floating layers (dropdown, modal,
  toast).
- **z-index scale, fixed** (`ux-guidelines.csv` #15 — "define a scale, don't use arbitrary
  large values"): `10` sticky table header · `20` sidebar/topbar · `30` dropdown/popover ·
  `40` modal overlay · `50` toast. `z-[9999]` is banned.

### Elevation & gradient (added 2026-08-17, `DECISIONS.md` 025)

Scoped strictly to page headers, the dashboard hero, and KPI/stat cards — **never** table
rows, form fields, or severity/tier/status indicators.

```css
--shadow-card:
  0 1px 2px 0 rgb(15 23 42 / 0.06), 0 1px 3px 0 rgb(15 23 42 / 0.1);
--shadow-float: 0 4px 12px 0 rgb(15 23 42 / 0.12);
--shadow-overlay: 0 12px 32px 0 rgb(15 23 42 / 0.18);
--gradient-hero: linear-gradient(135deg, #0369a1 0%, #0f172a 100%);
--gradient-accent: linear-gradient(90deg, #0369a1 0%, #38bdf8 100%);
```

### Glass system (added 2026-08-18, `DECISIONS.md` 028)

App-wide now — chrome, hero, KPI/stat cards, modals, popovers, nav. **Never** risk-semantic
surfaces (§2). Implemented in `app/globals.css` as `.glass-panel` / `.glass-panel-sm`
utility classes so no component hand-rolls `backdrop-filter` independently.

```css
--glass-surface: rgb(
  255 255 255 / 0.72
); /* light — high opacity, not the SaaS-default 10% */
--glass-border: rgb(15 23 42 / 0.08);
--glass-highlight: rgb(
  255 255 255 / 0.5
); /* inset top highlight, the "light source" cue */
--glass-blur: 20px;
--glass-blur-sm: 10px; /* nested/dense glass (cards inside a glass hero) */

/* dark mode */
--glass-surface: rgb(15 23 42 / 0.55);
--glass-border: rgb(148 163 184 / 0.16);
--glass-highlight: rgb(148 163 184 / 0.12);
```

Rules:

- Light-mode glass surface opacity is **72%+**, not the ~10% a generic glassmorphism preset
  suggests — below ~70% white, body text fails 4.5:1 against a busy aurora backdrop. This was
  flagged by the `ui-ux-pro-max` skill's own pitfall list before it was hit in practice.
- `@media (prefers-contrast: more)` falls back `.glass-panel` to a flat `--card` background,
  no blur — glass is a decoration, not a dependency for reading the page.
- The aurora-mesh backdrop (`--gradient-aurora`, `.aurora-backdrop`) stays in the
  institutional blue family (`#0369a1`/`#38bdf8`) already used for `--primary` — not the
  amber/purple a generic "fintech" preset suggests, which would compete with the locked
  risk-severity palette above.

### Motion

- 150–200ms, `ease-out`, on `transform` and `opacity` only — never `width`/`height`.
- Hover feedback via colour and border, never scale (scale shifts layout).
- `prefers-reduced-motion: reduce` honoured globally (`ux-guidelines.csv` #9, #99).
- Infinite animation is for loading indicators only (#12). No decorative movement.
- Added 2026-08-17 (`DECISIONS.md` 025): stat count-up and staggered list/chart entry are
  now sanctioned for the dashboard and KPI cards, built on `motion`, still gated to
  `transform`/`opacity` and still fully disabled under `prefers-reduced-motion`.

## 6. Accessibility floor

Priority 1 and 2 in the skill's rule set — treated as requirements, not aspirations. This is
a compliance product; an inaccessible compliance product is an embarrassment.

- [ ] 4.5:1 minimum on all text. `#475569` is the lightest permitted for body copy.
- [ ] Visible focus ring on every interactive element — `focus-visible:ring-2 ring-cta`.
      Never `outline-none` without a replacement.
- [ ] Every input has a `<label for>`. Placeholder text is not a label.
- [ ] `aria-label` on every icon-only button.
- [ ] Tab order follows visual order. The whole questionnaire is completable by keyboard.
- [ ] 44×44px minimum touch targets in the portal.
- [ ] Error messages sit adjacent to the field, are announced via `aria-live`, and say what
      to do — not just what is wrong.
- [ ] Async buttons disable and show progress; no double submission (#32, #61).
- [ ] Skeletons for anything over 300ms; reserved space so tables do not jump (#78).
- [ ] `prefers-reduced-motion` respected.
- [ ] SVG icons from **Lucide** only. **No emoji as icons**, anywhere.
- [ ] Responsive at 375 / 768 / 1024 / 1440. No horizontal page scroll — wide tables scroll
      inside their own container.

## 7. Portal-specific UX rules

Where MVP success is actually decided. A vendor who stalls generates the manual chasing this
platform exists to remove.

1. **Autosave, visibly.** Save per control with a "Saved 14:32" indicator. Never rely on a
   final submit button holding an hour of work.
2. **Honest progress.** Count only questions currently visible. Suppressed questions are
   excluded from both the denominator and the validator.
3. **Branching is explained, not silent.** When answering HOST-01 reveals four new questions,
   say so — an unannounced growing form feels like a trap.
4. **State evidence requirements up front.** Accepted types and size cap shown before the
   file picker opens, not as a rejection afterwards.
5. **Resume where they left off**, with the last-answered section expanded.
6. **Blockers listed at submit**, each a link that scrolls to and focuses the field.
7. **No dead ends.** Expired OTP, expired session, submitted assessment — every terminal
   state has a next action and a contact route.
8. **Plain language.** The vendor never sees `residual_score`, `control_id`, or `Tier 2`.
   Those are internal concepts.

## 8. Pre-delivery checklist

Run before any UI phase is called done, alongside the `TEST-CHECKLIST.md` gates.

**Visual** — no emoji icons · one icon set · no layout-shifting hover · semantic token names
(`bg-primary`, not `bg-slate-900`) · borders visible

**Interaction** — `cursor-pointer` on everything clickable · clear hover feedback ·
transitions 150–300ms · focus states visible

**Layout** — responsive at all four widths · no content behind sticky headers · consistent
container width · no horizontal page scroll

**Accessibility** — labels present · alt text present · colour never the sole indicator ·
`prefers-reduced-motion` honoured · keyboard-completable

**Risk-domain** — a `null` tier renders as a visible warning, never blank and never low ·
severity always icon + label + colour · every chart has a table alternative · the current
workspace is always visible
